# Вклад в MaxStat MCP

Присылайте исправления документации, конфигурации MCP-клиентов, изменения
публичных манифестов и метаданных, а также улучшения русскоязычного
аналитического skill. Проблемы совместимости описывайте с шагами воспроизведения.

MaxStat работает как облачный сервис. Его серверный код не входит в этот
репозиторий. Для новых серверных функций создавайте issue с описанием задачи.

## Перед pull request

1. Не добавляйте API-токены, персональные данные и другие секреты.
2. В примерах используйте `<API_TOKEN>` или переменную `MAXSTAT_API_TOKEN`.
3. Сохраняйте `X-API-Token` в готовых конфигурациях. Поддержка Bearer сервером
   не требует менять эти примеры.
4. Указывайте одну версию `1.2.4` во всех манифестах пакета.
5. Используйте kebab-case для имён плагинов и skill.
6. Проверяйте изменённые ссылки и конфигурации.
7. Укажите клиент и версию, на которых вы проверили изменение.

## Локальная проверка

Требуется Node.js 22 или новее.

```bash
npm run check
```

При обновлении справочника инструментов выполните сетевую проверку:

```bash
npm run check:api
```

Команда читает публичную OpenAPI-схему без токена и сравнивает имена 15 операций
и цены с `scripts/tool-contract.mjs`. Локальный валидатор по тому же контракту
проверяет таблицы README и skill. Сетевая проверка не вызывает платные методы.
Список MCP-инструментов проверяйте отдельно через авторизованный `tools/list`
в клиенте. Мониторинг и получатели уведомлений настраиваются в кабинете;
в MCP операций для них нет.

## Тексты

Пишите, что пользователь может сделать и как. Убирайте вводные фразы и повторы.
Даты указывайте рядом с цифрами и в истории изменений.
Отчёты о тестах и сверках оставляйте в PR.

## Новости сервиса, API и MCP

Изменения сервиса и API записывайте в [UPDATES.md](UPDATES.md), версии пакета —
в [CHANGELOG.md](CHANGELOG.md). Главные изменения кратко описывайте в разделе
«Что нового» README на русском и английском.

- Пишите, что может сделать пользователь и где включить функцию. Добавляйте
  ссылку на неё или документацию.
- Различайте кабинет, публичный REST API и MCP. Описывайте функцию сервиса
  после её появления в работающем интерфейсе или публичном контракте,
  а не только в исходниках.
- Даты выпуска берите из источника. Если их нет, датируйте обзор текущих
  возможностей. Исправление документации не называйте новой функцией API.
- Сравнивайте методы, параметры, ответы, авторизацию и стоимость всей
  OpenAPI-схемы. Изменение `info.version` не заменяет это сравнение,
  а REST-схема — авторизованный MCP `tools/list`.
- Сохраняйте ссылки на источники и ограничения, которые влияют на работу.
  Не публикуйте содержимое личного кабинета, настройки получателей,
  приватный код, архивы исходников и секреты.

Автоматизация обновляет пакет по понедельникам в 13:00 (`Europe/Moscow`).
Она читает свежий GitLab только в режиме read-only, публичную OpenAPI-схему,
страницы функций и счётчики MaxStat. При подтверждённых изменениях обновляет
весь затронутый публичный пакет: документацию, конфигурации, манифесты,
skill, проверки и демо. Изменения проходят локальные тесты, pull request и CI;
после успешных проверок попадают в `main`. Ошибка контракта или проверки
останавливает слияние. Недоступность источника не означает удаление функции.
Автоматизация не меняет production и не запускает деплой. Для запуска нужны
включённый Mac и Codex.

## Обновление счётчиков и GIF

Числа, дата и источник хранятся в `data/index-stats.json`. Из этого файла
формируются два блока README и первый кадр GIF. `npm run check` проверяет,
что значения совпадают.

Для обновления нужны Python 3, ffmpeg с фильтром `drawtext` и шрифты Arial
или DejaVu Sans. Команда читает публичную страницу MaxStat без токена:

```bash
npm run refresh:stats
```

При капче, ошибке страницы или рендера файлы и дата сохраняются. Если страница
открывается только в браузере, сохраните её публичный блок счётчиков
в игнорируемый каталог `.local/` и передайте время сохранения HTML в UTC:

```bash
node scripts/refresh-index-stats.mjs \
  --from-html .local/service-counters.html \
  --observed-at 2026-11-08T09:59:27.000Z
```

Старый снимок не заменит более новый. Не добавляйте сырые HTML-файлы
в репозиторий. Чтобы пересобрать GIF без обращения к сайту, выполните
`npm run render:demo`.

При нестандартной установке задайте пути в `MAXSTAT_FFMPEG`,
`MAXSTAT_FONT_REGULAR` и `MAXSTAT_FONT_BOLD`.

Для изменений Claude-compatible плагина дополнительно выполните:

```bash
claude plugin validate . --strict
claude plugin validate ./plugins/maxstat --strict
```

Общий валидатор проверяет пути, версию и MCP-конфигурацию Codex-плагина:

```bash
npm run validate
```
